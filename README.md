# Zyphere COMPLETE21 — AI Agent + Knowledge + Watchlist + Self-Learning + Video Maker + Long-Article Reader (ไซเฟอร์)

Zyphere เป็นผู้ช่วย AI ภาษาไทย/อังกฤษที่ทำงานผ่านเว็บ ต่อยอดจาก COMPLETE20 (อ่านยาวจบ / ไฟล์ PDF-DOCX-XLSX-PPTX / กันตัดกลางคัน) โดยเพิ่ม **ความจำถาวรแบบพกพา, watchlist, สรุปความเคลื่อนไหวเชิงรุก, ประวัติการเรียนรู้, จุดคืนสภาพอัตโนมัติ และ remote KV** เพื่อให้ข้อมูลอยู่รอดแม้ Render ฟรีรีสตาร์ท

## ความสามารถหลัก

- **สนทนาเป็นธรรมชาติ**: บุคลิกคงเส้นคงวา เข้าใจบริบทต่อเนื่อง ตอบกระชับเหมือนคุยกับคน
- **Agent ใช้เครื่องมือเอง**: ค้นเว็บ อ่านหน้าเว็บ ดูเวลา/อากาศ บันทึกความจำ และเรียนรู้หัวข้อใหม่
- **ความจำสะสม**: เก็บโปรไฟล์ ข้อเท็จจริง ความชอบ และโน้ต/บทเรียนลง `data/memory.json`
- **คลังความรู้ (ใหม่)**: ไซเฟอร์เรียนรู้หัวข้อต่าง ๆ แล้วสรุปเป็นโน้ตพร้อมแหล่งอ้างอิง เก็บใน `data/knowledge.json`
  - ค้นหา/ดู/ลบ/ล้างความรู้ได้จากเมนู **ตั้งค่า → คลังความรู้ / การเรียนรู้**
  - ความรู้ที่เกี่ยวข้องจะถูกแนบเป็นบริบทให้ AI ตอนตอบคำถามโดยอัตโนมัติ
  - เปิดโหมด Agent แล้วสั่งว่า “เรียนรู้เพิ่มเรื่อง ...” หรือให้ไซเฟอร์เรียกเครื่องมือ `learn_topic` / `recall_knowledge` เองได้
- **การเรียนรู้ตามตาราง (ใหม่)**: มีหลักสูตรหมุนเวียน 53 หัวข้อ (วิทยาศาสตร์ ประวัติศาสตร์ เศรษฐศาสตร์ สุขภาพ จิตวิทยา ทักษะการเรียนรู้ ฯลฯ)
  - เซิร์ฟเวอร์ตั้งเวลาเรียนรู้ทุก 6 ชั่วโมง (ปรับได้ 1–168 ชม. ในหน้าเว็บ)
  - ทำงานเบื้องหลังเป็น job มี progress ให้ดู
  - ถ้าเซิร์ฟเวอร์หลับ/ออฟไลน์ จะเรียนรู้ต่อเมื่อตื่นมา และมี `/api/learn/tick` สำหรับเรียกจาก cron ภายนอกได้
- **สร้างวิดีโอ**: สั่งสร้างคลิปสั้นจากหัวข้อ ระบบจะวางโครงเรื่อง ค้นภาพปลอดลิขสิทธิ์ ใส่ข้อความ สร้างเสียงบรรยายไทย/อังกฤษ และประกอบเป็น **MP4 1280×720** พร้อมเครดิตภาพ
- **แหล่งภาพฟรีที่รองรับ**
  - **Openverse** (ไม่ต้องมีคีย์) — ภาพ CC0 / Public Domain / CC BY
  - **Wikimedia Commons** (ไม่ต้องมีคีย์) — ใช้เป็นแหล่งสำรอง
  - **Pexels / Pixabay / Unsplash** (ไม่บังคับ; ใส่คีย์ผ่าน environment variable เพื่อคุณภาพ/ตัวเลือกเพิ่ม)
- **เสียงพูด**: TTS ผ่านเซิร์ฟเวอร์ (`/tts`) หรือเสียงในเบราว์เซอร์ พร้อมตัดอีโมจิ/สัญลักษณ์ที่ไม่ใช่คำพูดออกก่อนอ่าน
- **อ่านเอกสารยาวจนจบ (ใหม่)**: แนบไฟล์ยาวหรือวางบทความยาว ๆ แล้วสั่งสรุป ระบบจะแบ่งอ่านทีละส่วน สรุปย่อย แล้วเรียบเรียงคำตอบสุดท้ายให้ครบทุกประเด็น — ไม่ตัดกลางคัน
  - รองรับไฟล์ข้อความ, **PDF, DOCX, XLSX/XLS, PPTX** และไฟล์ข้อความอื่น ๆ สูงสุด ~200,000 ตัวอักษรต่อไฟล์
  - แสดงความคืบหน้า “กำลังอ่านส่วนที่ n/N” ระหว่างทำงาน
  - คำตอบที่ยาวเกินขีดจำกัดของโมเดลจะถูกขอต่อโดยอัตโนมัติจนจบ
- **ความสามารถเดิม**: แนบ/อ่านไฟล์หลายชนิด, ประวัติแชท, โหมดเสียงต่อเนื่อง, โหมดเขียนโค้ด, โหมดมืด, มือถือ
- **Watchlist (COMPLETE21)**: เพิ่มหัวข้อที่อยากให้ไซเฟอร์คอยอัปเดต ระบบจะเรียนรู้หัวข้อเหล่านี้ก่อนหลักสูตรหมุนเวียน
- **สรุปเชิงรุก (COMPLETE21)**: เปิดแอปขึ้นการ์ดสรุปตอนคุณไม่อยู่ พร้อมคำแนะนำว่าควรทำต่ออะไร
- **คำสั่งในแชท (COMPLETE21)**: `ติดตามหัวข้อ ...`, `มีอะไรใหม่`, `จำไว้ว่า ...` ใช้ได้แม้ปิดโหมด Agent
- **สำรอง/กู้คืน + snapshot (COMPLETE21)**: ระบบสร้างจุดคืนสภาพก่อนล้างคลัง/กู้คืน/ดึงข้อมูล
- **Remote KV (COMPLETE21)**: เก็บความจำ/ความรู้/การเรียนรู้/watchlist บนคลาวด์ด้วย Upstash Redis REST

## การติดตั้งและใช้งาน

ต้องมี Python 3.9+ และอินเทอร์เน็ต (สำหรับค้นภาพ TTS และการเรียนรู้)

```bash
pip install -r requirements.txt
python app.py
```

เปิดเบราว์เซอร์ที่ `http://localhost:8000`

- กด **ตั้งค่า** แล้วใส่คีย์ AI อย่างน้อย 1 รายการ (Groq / Gemini / OpenRouter / Hugging Face)
- ช่อง **เซิร์ฟเวอร์ Zyphere** ใช้ระบุ backend สำหรับเสียง/วิดีโอ/Agent/การเรียนรู้
  - ถ้าเปิดหน้าเว็บผ่าน `python app.py` หรือ Render โดยตรง ระบบจะตรวจพบ backend ให้อัตโนมัติ (เว้นว่างได้)
  - ถ้าเปิดหน้าเว็บจากที่อื่น (เช่น GitHub Pages) ให้ใส่ URL ของ backend เช่น `https://zyphere-ai-agent.onrender.com`
- เปิด **โหมด Agent** เพื่อให้ค้นเว็บ/อ่านเว็บ/จำข้อมูล/เรียนรู้ได้
- เปิด **คลังความรู้** ที่เมนูตั้งค่า เพื่อดูความรู้ที่สะสมไว้ หรือสั่งเรียนรู้หัวข้อใหม่
- สั่งวิดีโอโดยกดปุ่ม **วิดีโอ** (ไอคอนฟิล์ม) หรือพิมพ์ เช่น
  - `สร้างวิดีโอ เรื่อง ประโยชน์ของการออกกำลังกาย 30 วินาที`
  - `ทำคลิป เกี่ยวกับ เมืองหลวงน่าเที่ยวในเอเชีย 45 วินาที`

## การอ่านเอกสารยาว (COMPLETE20)

ปัญหาเดิม: ระบบตัดข้อความที่ ~6,000 ตัวอักษร, ตั้งเพดานคำตอบต่ำ, และไม่สนใจสัญญาณว่าโมเดลตอบไม่จบ ทำให้สรุปบทความยาวขาดกลางทาง

วิธีใหม่:

1. **อ่านครบทุกส่วน**: ข้อความถูกแบ่งเป็นก้อนละ ~7,000 ตัวอักษร ตามขอบเขตย่อหน้า/ประโยค แล้วสรุปทีละก้อน
2. **รวมบันทึกสาระ**: ถ้าบันทึกย่อยเยอะเกินไป ระบบจะรวมเป็นชุดเล็กลงก่อน
3. **เรียบเรียงครั้งสุดท้าย**: สร้างคำตอบตามคำขอของผู้ใช้ (สรุป/วิเคราะห์/ตอบคำถาม) โดยสั่งให้เขียนจนจบและห้ามทิ้งประเด็น
4. **กันคำตอบถูกตัด**: ตรวจ `finish_reason` / `finishReason` แล้วขอให้โมเดลเขียนต่ออัตโนมัติสูงสุด 3 รอบ
5. **กันค้าง**: ทุกคำขอมี timeout แบบนับจากข้อมูลล่าสุด และลองใหม่เมื่อโดน rate limit (429) โดยรอตามที่ผู้ให้บริการแนะนำ
6. **แสดงความคืบหน้า**: UI ใช้การวาดแบบ throttle จึงไม่หนักเครื่อง และบอกว่ากำลังอ่านส่วนไหน

ขีดจำกัดที่ควรรู้: ไฟล์สแกน PDF ที่เป็นรูปภาพยังอ่านข้อความไม่ได้ (ต้องมี OCR) และเอกสารที่ใหญ่กว่า 200,000 ตัวอักษรจะถูกตัดที่เพดานนี้

## COMPLETE21 — ความจำถาวร / ติดตาม / สรุปเชิงรุก

- **Watchlist**: เพิ่ม/เลิกติดตามหัวข้อได้ในคลังความรู้ หัวข้อถึงกำหนดจะเรียนรู้ก่อนหลักสูตรอื่น และแจ้งเมื่อมีฉบับใหม่

- **Briefing**: การ์ดสรุปตอนคุณไม่อยู่ แสดงความรู้ใหม่ หัวข้อที่อัปเดต ประวัติ และคำแนะนำ
- **คำสั่งในแชท**: `ติดตาม AI ล่าสุด`, `มีอะไรใหม่`, `จำไว้ว่า ...` ใช้ได้แม้ปิด Agent
- **ความจำอัตโนมัติ**: สกัดข้อเท็จจริง/ความชอบจากบทสนทนาแล้วบันทึกทันทีเมื่อเชื่อมเซิร์ฟเวอร์
- **ประวัติการเรียนรู้ + snapshot**: ดูย้อนหลังและกู้คืนจากจุดคืนสภาพอัตโนมัติได้
- **Remote KV**: ดันข้อมูลขึ้นคลาวด์ด้วย Upstash REST แล้วดึงกลับตอน restart

## การเรียนรู้และคลังความรู้ทำงานอย่างไร

1. ผู้ใช้กดเรียนรู้หัวข้อ หรือเซิร์ฟเวอร์ถึงรอบเวลาที่ตั้งไว้
2. ระบบดึงข้อมูลจาก Wikipedia (ไทย/อังกฤษ) เป็นหลัก ถ้าไม่พอจึงเสริมจากเว็บที่คัดคุณภาพ
3. สรุปเป็นโน้ต: หัวข้อ, สรุป, ประเด็นสำคัญ, แท็ก, แหล่งอ้างอิง
   - ค่าเริ่มต้นใช้การสกัดข้อความ (extractive) จากย่อหน้าที่สะอาด
   - ถ้าตั้งคีย์ LLM ฝั่งเซิร์ฟเวอร์ จะสรุปด้วย AI คุณภาพสูงขึ้น
4. บันทึกลง `data/knowledge.json` (หัวข้อซ้ำจะอัปเดตเป็นฉบับใหม่)
5. ตอนสนทนา ระบบค้นความรู้ที่เกี่ยวข้อง (สูงสุด 4 เรื่อง) แนบเป็นบริบทให้โมเดลใช้ตอบ

### คีย์ LLM ฝั่งเซิร์ฟเวอร์ (ไม่บังคับ แต่แนะนำ)

คีย์ที่ใส่ในหน้าเว็บใช้ฝั่งเบราว์เซอร์ ไม่สามารถใช้สรุปฝั่งเซิร์ฟเวอร์ได้ หากต้องการสรุปคุณภาพสูงให้ตั้ง environment variable บน Render:

```bash
GROQ_API_KEY=...
OPENROUTER_API_KEY=...
GEMINI_API_KEY=...
# ไม่บังคับ: ระบุโมเดลเอง
LEARN_LLM_MODEL=...
# ไม่บังคับ: ป้องกัน /api/learn/tick ด้วยโทเคน
LEARN_TOKEN=...
# ไม่บังคับ: ป้องกันสำรอง/กู้คืน/ดึงจากคลาวด์
BACKUP_TOKEN=...
```

ถ้าไม่ตั้ง ระบบยังเรียนรู้ได้ด้วยการสกัดข้อความ

### Remote KV (ไม่บังคับ)

```bash
REMOTE_KV_URL=https://xxx.upstash.io
REMOTE_KV_TOKEN=...
```

ใช้ Upstash Redis REST (`/set/<key>`, `/get/<key>`) เก็บ `zyphere:memory`, `zyphere:knowledge`, `zyphere:learning`, `zyphere:watch` ระบบดันอัตโนมัติเมื่อมีการเปลี่ยนแปลง และดึงกลับตอนสตาร์ท หาก Render รีสตาร์ทและ `data/` หาย ข้อมูลจะกลับมาจากคลาวด์

## การสร้างวิดีโอทำงานอย่างไร

1. หน้าเว็บใช้คีย์ AI ของคุณสร้างโครงเรื่อง (ถ้าไม่มีคีย์จะใช้โครงสำรอง)
2. ส่งงานไปที่ `POST /api/video` (ทำงานเบื้องหลังเป็น job)
3. เซิร์ฟเวอร์ค้นภาพจากแหล่งฟรี แล้วดาวน์โหลดภาพที่เหมาะสม
4. สร้างฉากด้วย Pillow (ครอปภาพ + ใส่ข้อความไทย/อังกฤษ)
5. สร้างเสียงบรรยายด้วย edge-tts
6. เรนเดอร์แต่ละฉากและรวมเป็น MP4 ด้วย ffmpeg (ผ่าน `imageio-ffmpeg`)
7. หน้าเว็บ poll สถานะที่ `GET /api/video/status?id=...` แล้วแสดงวิดีโอให้เล่น/ดาวน์โหลด

ไฟล์วิดีโอจะอยู่ใน `media/` และเข้าถึงได้ที่ `/media/video_xxx.mp4`

## API หลัก

| Endpoint | วิธี | หน้าที่ |
|---|---|---|
| `/api/health` | GET | ตรวจสถานะ/เวอร์ชัน/ฟีเจอร์ |
| `/api/search?q=...` | GET | ค้นเว็บ |
| `/api/fetch?url=...` | GET | อ่านเนื้อหาหน้าเว็บ |
| `/api/memory` | GET/POST | อ่าน/อัปเดตความจำ |
| `/api/knowledge?q=...&limit=...` | GET | ค้น/ดูคลังความรู้ |
| `/api/knowledge` | POST | ลบ (`{"delete":"id"}`) หรือล้าง (`{"clear":true}`) |
| `/api/learn/config` | GET/POST | อ่าน/ปรับการตั้งค่าการเรียนรู้ |
| `/api/learn` | POST | เริ่มเรียนรู้ (`topic` หรือ `{"rotate":true,"count":1}`) |
| `/api/learn/status?id=...` | GET | ดูสถานะ job / รายการ job |
| `/api/learn/once` | POST | เรียนรู้ทันทีแบบรอผล (`{"topic":"..."}`) |
| `/api/learn/tick` | GET | ให้ cron ภายนอกเรียกให้เรียนรู้หนึ่งรอบ |
| `/api/images?q=...&n=...` | GET | ค้นภาพฟรี (ทดสอบแหล่งภาพ) |
| `/api/video` | POST | สร้างงานวิดีโอ (`topic`, `lang`, `seconds`, `script`, `style`, `rate`) |
| `/api/video/status?id=...` | GET | ดูสถานะ/ลิงก์วิดีโอ/เครดิต |
| `/api/video/list` | GET | รายการงานล่าสุด |
| `/tts?text=...&lang=th` | GET | เสียงพูด MP3 |
| `/api/watch` | GET/POST | ดู/เพิ่ม/ลบ/ล้างหัวข้อติดตาม |
| `/api/briefing?since=...` | GET | สรุปความเคลื่อนไหว + คำแนะนำ |
| `/api/learn/history` | GET | ประวัติการเรียนรู้ |
| `/api/backup` | GET | ดาวน์โหลดไฟล์สำรอง (ต้องใช้ `token`) |
| `/api/restore` | POST | กู้คืนจากไฟล์ (ต้อง `token` + `confirm`) |
| `/api/snapshots` | GET/POST | รายการ/สร้างจุดคืนสภาพ |
| `/api/snapshots/restore` | POST | กู้คืนจากจุดคืนสภาพ |
| `/api/storage` | GET | สถานะที่เก็บ |
| `/api/storage/sync` | POST | ดันขึ้นคลาวด์ |

## ข้อจำกัดที่สำคัญ (โปร่งใส)

- **การเรียนรู้ต้องให้เซิร์ฟเวอร์ออนไลน์**: Render แผนฟรีจะหลับเมื่อไม่มีคนใช้ ทำให้การเรียนรู้ตามเวลาไม่ต่อเนื่อง 100%
- **พื้นที่เก็บข้อมูลไม่ถาวรบนแผนฟรี**: `data/` และ `media/` หายเมื่อรีสตาร์ท/รีดีพลอย ต้องใช้ persistent disk หรือฐานข้อมูลภายนอก (เช่น Supabase/Postgres) เพื่อเก็บถาวรจริง
- **คุณภาพการสรุปแบบสกัดข้อความ** ยังหยาบกว่าการสรุปด้วย LLM และภาษาไทยอาจตัดประโยคไม่สมบูรณ์ในบางกรณี
- **ไม่ใช่ AI สร้างวิดีโอแบบ generative**: เป็นการประกอบภาพนิ่ง + ข้อความ + เสียงบรรยาย ไม่ใช่วิดีโอเคลื่อนไหวจากโมเดลวิดีโอ
- **คุณภาพ/ความเกี่ยวข้องของภาพ** ขึ้นกับผลค้นหาจากแหล่งฟรี; คำค้นภาษาอังกฤษจะให้ผลดีกว่า
- **เวลาเรนเดอร์วิดีโอ** ขึ้นกับความยาวคลิปและทรัพยากรเซิร์ฟเวอร์ โดยเฉพาะ Render แผนฟรี (CPU ต่ำ)
- **ลิขสิทธิ์**: แม้ภาพจะมาจากแหล่งฟรี แต่เงื่อนไขแต่ละภาพต่างกัน ระบบกรองและใส่เครดิตให้ แต่ผู้ใช้ควรตรวจสอบก่อนนำไปใช้เชิงพาณิชย์
- **“เรียนรู้/พัฒนาเอง”** คือการสะสมความรู้/ความจำ ไม่ใช่การแก้โค้ดหรือปรับโมเดลของตัวเองโดยอัตโนมัติ
- **การคุมอุปกรณ์/เครื่องจักรจริง** ต้องเชื่อมผ่านเครื่องมือ/บริการภายนอก (เช่น Home Assistant, MQTT, local companion) พร้อมสิทธิ์และการยืนยัน
- ดูแผนพัฒนาต่อและช่องว่างที่เหลือได้ที่ `ROADMAP.md`

## โครงสร้างไฟล์

- `index.html` — หน้าเว็บ + ลูป Agent + คลังความรู้ + ตัวสร้างวิดีโอฝั่ง client
- `app.py` — เซิร์ฟเวอร์: หน้าเว็บ, TTS, ค้นเว็บ/อ่านเว็บ, ความจำ, การเรียนรู้, คลังความรู้, ค้นภาพ, เรนเดอร์วิดีโอ
- `ROADMAP.md` — แผนพัฒนาและช่องว่างที่ยังต้องเติม
- `fonts/` — ฟอนต์ Noto Sans Thai (Regular/Bold) สำหรับข้อความในวิดีโอ
- `data/memory.json` — ความจำสะสม (สร้างอัตโนมัติ)
- `data/knowledge.json` — คลังความรู้ (สร้างอัตโนมัติ)
- `data/learning.json` — สถานะ/การตั้งค่าการเรียนรู้ (สร้างอัตโนมัติ)
- `media/` — ไฟล์วิดีโอที่สร้าง (สร้างอัตโนมัติ)
- `libs/` — ไลบรารีอ่านไฟล์ฝั่งเบราว์เซอร์
- `requirements.txt` — แพ็กเกจ Python
- `.gitignore` — กันไม่ให้อัปโหลดข้อมูลส่วนตัว/ไฟล์ที่สร้างขึ้น

## การ deploy บน Render

- **Build Command**: `pip install -r requirements.txt`
- **Start Command**: `python app.py`
- **Instance Type**: Free
- หลัง deploy เปิด URL ของบริการ แล้วตั้งค่าคีย์ AI ในแอป
- ไม่ต้องตั้งค่า `PORT` เอง (Render กำหนดให้ และ `app.py` รองรับอยู่แล้ว)
- หากต้องการคีย์ภาพ/LLM เพิ่ม ให้ใส่ใน Environment ของ Render ตามข้อด้านบน

> หมายเหตุ: อย่าอัปโหลดไฟล์ที่มีคีย์ API ขึ้น GitHub สาธารณะ
